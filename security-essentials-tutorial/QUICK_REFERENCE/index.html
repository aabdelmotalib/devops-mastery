    Security Essentials Tutorial: Quick Reference

    A comprehensive DevOps security curriculum teaching secure-by-default system design, from application code to infrastructure and supply chain security.

    Contents at a Glance

    Documentation Structure

    security-essentials-tutorial/
├── README.md                          [Overview, track context, security ROI]
├── QUICK_REFERENCE.md                 [This file - quick navigation]
├── FINAL_PROJECT.md                   [Capstone: Secure deployment pipeline]
│
└── docs/                              [8 Core Security Modules]
    ├── 01-application-security-fundamentals.md    [Secure coding, SAST, dependency scanning]
    ├── 02-infrastructure-security.md              [Network policies, RBAC, encryption]
    ├── 03-supply-chain-security.md                [Container scanning, image signing]
    ├── 04-compliance-audit.md                     [HIPAA, PCI-DSS, GDPR, audit logging]
    ├── 05-incident-response.md                    [Detection, containment, forensics]
    ├── 06-api-security.md                         [API authentication, rate limiting]
    ├── 07-container-security.md                   [Runtime security, admission control]
    └── 08-secrets-management.md                   [Secret storage, rotation, sprawl]

    Each Module Contains

    • Security Concepts: Threats, mitigations, industry best practices
    • Production Use Cases: Real-world attack scenarios and defenses
    • Tool Examples: CLI commands for popular security tools
    • Code Patterns: Secure coding examples and anti-patterns
    • Common Mistakes: Misconfigurations and security pitfalls
    • Operational Guidance: DevOps integration and automation
    • 5 MCQ Questions: Assess understanding
    • 2 Hands-On Labs: Practical security exercises
    • 1 Production Incident Scenario: Breach response and prevention

    Each module explains how its security layer fits into this model.

    Module Breakdown

    Module 1: Application Security Fundamentals (3-4 hours)

    Threat Model: Code vulnerabilities, dependency risks, hardcoded secrets Topics: Secure coding practices, SAST/DAST, dependency scanning, secrets management Tools: OWASP Top 10, Snyk, Trivy, SonarQube, git-secrets Key Skill: Shift left—catch security issues during development

    Module 2: Infrastructure Security (3-4 hours)

    Threat Model: Unauthorized access, network lateral movement, unencrypted data Topics: IAM/RBAC, VPC/network policies, encryption at rest/in transit, hardening Tools: Cilium, Falco, sealed-secrets, cert-manager, network policies Key Skill: Defense in depth with least privilege access

    Module 3: Supply Chain Security (2-3 hours)

    Threat Model: Compromised container images, malicious dependencies, unsigned artifacts Topics: Container scanning, image signing, artifact verification, SBOMs Tools: Sigstore, Cosign, SBOM tools, Policy Engine, admission controllers Key Skill: Trust no external code—verify everything

    Module 4: Compliance & Audit (2-3 hours)

    Threat Model: Regulatory violations, audit failures, lack of accountability Topics: HIPAA, PCI-DSS, GDPR, SOC 2, audit logging, policy enforcement Tools: OPA/Gatekeeper, audit logs, compliance scanners Key Skill: Automation ensures compliance, not just documentation

    Module 5: Incident Response (3-4 hours)

    Threat Model: Active breach, data exfiltration, service disruption Topics: Detection strategies, containment, forensics, post-mortems, runbooks Tools: ELK Stack, Prometheus, threat intelligence platforms, log aggregation Key Skill: Response speed reduces blast radius and damage

    Module 6: API Security (2-3 hours)

    Threat Model: Unauthorized API access, injection attacks, data exposure Topics: Authentication/authorization, rate limiting, input validation, TLS Tools: Kong, OAuth 2.0, API gateways, WAF rules Key Skill: APIs are attack surface—protect them explicitly

    Module 7: Container Security (2-3 hours)

    Threat Model: Container escape, privilege escalation, runtime manipulation Topics: Runtime monitoring, admission control, pod security policies, image scanning Tools: Falco, AppArmor/SELinux, Kubernetes pod security, container runtime security Key Skill: Container != VM—different security model required

    Module 8: Secrets Management (2-3 hours)

    Threat Model: Secrets in git, log leakage, unauthorized secret access Topics: Secret rotation, least privilege secret access, external vaults Tools: HashiCorp Vault, Kubernetes Secrets, sealed-secrets, AWS/GCP KMS Key Skill: Secrets in code = guaranteed breach; treat as critical infrastructure

    Learning Prerequisites

    Required Knowledge: - Basic Linux/command line - Container fundamentals (Docker) - Kubernetes basics (pods, deployments, services) - Networking fundamentals (TCP/IP, ports, firewalls)

    Helpful But Not Required: - DevOps/CI-CD experience - Cloud platform experience (AWS/GCP/Azure) - Programming experience (examples in Python/Go)

    Key Takeaways

    ✅ Security is a Process, Not a Product - Continuous monitoring, testing, and improvement - Embedded in every stage of deployment pipeline

    ✅ Shift Left - Catch issues early: development > testing > production - Automated scanning saves time and prevents breaches

    ✅ Defense in Depth - Multiple layers: application, infrastructure, supply chain - No single point of failure

    ✅ Automation Enables Both Security and Speed - Policy enforcement and compliance automation - Faster deployments with confidence

    ✅ Incident Response Readiness - Detection and response speed = cost savings - Runbooks and practice drills reduce panic

    Quick Command Reference

    Application Security

    # Scan dependencies
snyk test --severity-threshold=high

# Scan container images
trivy image --severity HIGH,CRITICAL myapp:latest

# Check for hardcoded secrets
git-secrets --scan

    Infrastructure Security

    # Test Kubernetes pod security policy
kubectl auth can-i get pods --as=system:serviceaccount:default:attack

# View network policies
kubectl get networkpolicies

# Check RBAC
kubectl get rolebindings --all-namespaces

    Compliance & Audit

    # Check Kubernetes audit logs
kubectl logs -n kube-system -l component=kube-apiserver

# Test OPA policies
opa test -v

    Incident Response

    # Query ELK for suspicious activity
GET /logs/_search { "query": { "match": { "event.action": "privilege_escalation" } } }

# Extract container logs for forensics
docker logs --timestamps <container_id> > forensics.log
