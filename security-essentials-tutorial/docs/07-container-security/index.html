    Container Security

    Overview

    Container Security protects containerized applications from vulnerabilities, escape attacks, and runtime threats. It spans building secure images, scanning for vulnerabilities, and enforcing policies at runtime.

    Mental Model

    Container Attack Surface:

Host OS (Linux kernel)
    ↓
┌─────────────────────────────┐
│  Container Runtime (Docker) │
│  - Orchestrates containers  │
│  - Manages resources        │
├─────────────────────────────┤
│  Container Image Layer 3    │  ← Attacker: Supply chain attack
│  Container Image Layer 2    │     (Inject malware in base image)
│  Base Image (Ubuntu/Alpine) │  ← Attacker: Use vulnerable base
├─────────────────────────────┤
│  Application Code           │  ← Attacker: App vulnerabilities
│  (Your code + dependencies) │     (Known CVEs in libraries)
├─────────────────────────────┤
│  Container Runtime (Proc)   │  ← Attacker: Container escape
│  (Gives access to host OS)  │     (Kernel exploit → host access)
└─────────────────────────────┘
         ↓
Host OS (Can be compromised if container escapes)

Defense layers:
1. Build time: Scan images, use minimal base images
2. Registry time: Sign images, verify signatures
3. Deploy time: Admission controllers block unsigned
4. Runtime: Security policies, process isolation
5. Monitoring: Detect suspicious behavior

    Building Secure Container Images

    Multi-Stage Builds (Reduce Surface Area)

    # ❌ WRONG: Single stage, includes build tools
FROM ubuntu:22.04
RUN apt-get update && apt-get install -y \
    build-essential \
    gcc \
    git
COPY . /app
RUN cd /app && make
ENTRYPOINT ["/app/binary"]

# Result: Image includes gcc, make, git (unnecessary)
# File size: 1GB
# Attack surface: Compile tools, apt packages

# ✅ CORRECT: Multi-stage build
FROM ubuntu:22.04 AS builder
RUN apt-get update && apt-get install -y build-essential gcc
COPY . /app
RUN cd /app && make

FROM ubuntu:22.04
COPY --from=builder /app/binary /app/binary
ENTRYPOINT ["/app/binary"]

# Result: Final image has only app binary
# File size: 100MB
# Attack surface: Minimal

    Minimal Base Images

    # ❌ WRONG: Ubuntu as base
FROM ubuntu:22.04  # 77MB, includes many packages
RUN apt-get update && apt-get install -y python3 python3-pip
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY app.py .
ENTRYPOINT ["python3", "app.py"]

# ✅ CORRECT: Alpine or distroless
FROM python:3.10-alpine  # 50MB, minimal OS
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY app.py .
ENTRYPOINT ["python3", "app.py"]

# Even better: Distroless (no shell, no OS tools)
FROM gcr.io/distroless/python3  # 20MB, just Python runtime
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY app.py .
ENTRYPOINT ["python3", "app.py"]

    Security Best Practices in Dockerfile

    FROM python:3.10-alpine

# 1. Don't run as root
RUN addgroup -g 1000 appuser && \
    adduser -U -u 1000 appuser

# 2. Minimize layers (fewer = smaller image)
RUN apk update && \
    apk add --no-cache curl && \
    pip install requests && \
    apk del apk-tools && \
    rm -rf /var/cache/apk/*

# 3. Pin versions (reproducibility)
RUN pip install requests==2.28.1 flask==2.2.2

# 4. Don't store secrets in image
# ❌ WRONG: RUN echo "SECRET=abc123" > /app/.env
# ✅ RIGHT: Use environment variables or secrets at runtime

# 5. Scan before building
# (This is in CI/CD, not Dockerfile)

WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt

COPY --chown=appuser:appuser . .

# 6. Read-only root filesystem
RUN chmod u+w /tmp  # Only /tmp writable

USER appuser

# 7. Drop unnecessary capabilities
# (Specify in Kubernetes, not Dockerfile)

EXPOSE 8080
ENTRYPOINT ["python", "app.py"]

    Image Scanning & Vulnerability Detection

    Trivy: Comprehensive Image Scanner

    # Scan local image
trivy image myapp:1.0

# Output:
# myapp:1.0 (debian 11.1)
# Total: 23 vulnerabilities
# CRITICAL:  2
# HIGH:      8
# MEDIUM:    13

# Scan with detailed CVE info
trivy image --severity HIGH,CRITICAL \
  --format json \
  myapp:1.0 > scan-results.json

# Fail build if critical vulnerabilities
trivy image --severity CRITICAL \
  --exit-code 1 \
  myapp:1.0

# Scan in CI/CD
# github action, gitlab runner, etc.

    Grype: Quick Vulnerability Check

    # Similar to trivy
grype myapp:1.0

# Shows:
# Package          Version    Vulnerability
# openssl          1.1.1g     CVE-2021-3999 (Critical)
# curl             7.64.1     CVE-2020-8169 (High)

# With CycloneDX output (SBOM)
grype myapp:1.0 -o cyclonedx > sbom.xml

    Container Runtime Security

    seccomp (Secure Computing Mode)

    Restrict system calls kernel exposes to containers:

    {
  "defaultAction": "SCMP_ACT_ERRNO",
  "defaultErrnoRet": 1,
  "archMap": [
    {
      "architecture": "SCMP_ARCH_X86_64",
      "subArchitectures": ["SCMP_ARCH_X86"]
    }
  ],
  "syscalls": [
    {
      "names": [
        "read",
        "write",
        "open",
        "close",
        "stat",
        "fstat",
        "lstat",
        "poll",
        "brk",
        "rt_sigreturn"
      ],
      "action": "SCMP_ACT_ALLOW"
    },
    {
      "names": ["ptrace"],
      "action": "SCMP_ACT_ERRNO",
      "errnoRet": 1
    }
  ]
}

    Use in Kubernetes:

    apiVersion: v1
kind: Pod
metadata:
  name: secure-pod
spec:
  securityContext:
    seccompProfile:
      type: Localhost
      localhostProfile: secure-profile.json
  containers:
  - image: myapp:1.0
    name: app

    AppArmor: Mandatory Access Control

    # AppArmor profile for container
profile container-profile flags=(attach_disconnected,mediate_deleted) {
  include <abstractions/base>

  # Allow reads only from /app
  /app/** r,

  # Allow writes only to /tmp
  /tmp/** rw,

  # Block access to sensitive files
  deny /etc/shadow rwx,
  deny /root/** rwx,
  deny /sys/kernel/** rwx,

  # Allow network (TCP only, not raw sockets)
  network inet tcp,

  # Block dangerous syscalls
  deny ptrace,
}

    Apply in Kubernetes:

    apiVersion: v1
kind: Pod
metadata:
  annotations:
    container.apparmor.security.beta.kubernetes.io/app: localhost/container-profile
spec:
  containers:
  - image: myapp:1.0
    name: app

    Container Escape Prevention

    Privileged Container Misuse

    # ❌ WRONG: Privileged container
apiVersion: v1
kind: Pod
metadata:
  name: privileged-pod
spec:
  containers:
  - image: ubuntu:22.04
    name: app
    securityContext:
      privileged: true  # Has root, can escape kernel
      # Can mount host filesystem
      # Can load kernel modules
      # Can disable security controls

# ✅ CORRECT: Restricted container
apiVersion: v1
kind: Pod
metadata:
  name: secure-pod
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    fsGroup: 1000
    seccompProfile:
      type: RuntimeDefault
    seLinuxOptions:
      level: "s0:c123,c456"

  containers:
  - image: myapp:1.0
    name: app
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      runAsNonRoot: true
      runAsUser: 1000
      capabilities:
        drop:
        - ALL
        add:
        - NET_BIND_SERVICE  # Only if needed

    resources:
      requests:
        cpu: 100m
        memory: 128Mi
      limits:
        cpu: 500m
        memory: 256Mi

    Kernel Vulnerability Mitigation

    # Keep kernel patched (highest impact for container security)
# Container security = host OS security

# Check kernel version
uname -r

# CVE-2021-22555: Privilege escalation in netfilter
# Affects: Linux < 5.11.2
# Fix: Update kernel

# CVE-2022-0847: Overwrite data in arbitrary files (Dirty Pipe)
# Affects: Linux < 5.16.11, 5.15.25
# Fix: Update kernel

    Container Image Signing & Verification

    # Sign images with Cosign
cosign sign --key cosign.key myregistry/myapp:1.0

# Verify before deployment
cosign verify --key cosign.pub myregistry/myapp:1.0
# Output: Verification successful!

# Kubernetes admission controller enforces
# kubectl cannot deploy unsigned images

    Common Mistakes

    Mistake 1: Running as root in containers 

    # ❌ WRONG
FROM ubuntu:22.04
COPY app /app
ENTRYPOINT ["/app/binary"]
# Runs as root (PID 1 = root)
# If app is compromised: attacker is root

# ✅ CORRECT
FROM ubuntu:22.04
RUN addgroup -g 1000 appuser && adduser -u 1000 appuser
COPY --chown=appuser:appuser app /app
USER appuser
ENTRYPOINT ["/app/binary"]
# Runs as user 1000 (unprivileged)

    Mistake 2: Building images with secrets 

    # ❌ WRONG
ARG DATABASE_PASSWORD=secret123
RUN echo "DB_PASS=${DATABASE_PASSWORD}" >> /app/.env
# Secret in image layer history forever
# `docker history` reveals secret

# ✅ CORRECT: Use BuildKit secrets
# docker build --secret db_pass=/path/to/secret.txt .

# Dockerfile
# syntax=docker/dockerfile:1
FROM ubuntu:22.04
RUN --mount=type=secret,id=db_pass \
    cat /run/secrets/db_pass > /tmp/setup.sh && \
    bash /tmp/setup.sh && \
    rm /tmp/setup.sh
# Secret never stored in layer

    Mistake 3: Large base images 

    # ❌ WRONG
FROM ubuntu:22.04  # 77MB
COPY app /app
# Lots of unnecessary packages

# ✅ CORRECT
FROM alpine:3.17  # 7MB
COPY app /app
# Or even smaller
FROM gcr.io/distroless/base  # 2MB
COPY app /app

    Mistake 4: Scanning only at build, not runtime 

    # ❌ WRONG:
# Build container
# Scan once: "No vulnerabilities"
# Deploy to production
# 6 months later: New CVE discovered
# Old container still deployed with vulnerability

# ✅ CORRECT:
# Daily scanning of running containers
# Alert if known CVE found in live image
# Auto-remediate or force redeploy

    Mistake 5: Trusting public images without verification 

    # ❌ WRONG
FROM ubuntu:latest  # Latest version, no signature
FROM python:3.10    # No verification

# ✅ CORRECT
FROM ubuntu@sha256:abc123...  # Pin exact image hash
FROM python:3.10-alpine  # Specific, signed version
# Verify image before use
docker pull --disable-content-trust=false python:3.10

    Production Incident: Container Escape

    Scenario: "Attacker escaped from container to host OS, compromised entire cluster"

    Investigation: 

    # 1. Check container logs for escape attempts
docker logs vulnerable-container | grep -i "escape\|privilege"

# 2. Check host for unauthorized access
lastlog -u root | grep -v "root"
sudo journalctl -xe | grep -i "unauthorized"

# 3. Check for kernel exploit (common escape vector)
# Vulnerable: Linux 4.4 (EOL)
# Attack: CVE-2021-22555 (netfilter escape)

# 4. Verify container was privileged
docker inspect vulnerable-container | jq '.HostConfig.Privileged'
# Result: true (VULNERABLE!)

    Root Cause: - Container ran as root - Container was privileged (–privileged flag) - Host kernel had known CVE - No security policies enforced

    Solution: 

    # 1. Remove privileged mode
# (Immediate)
kubectl delete pod vulnerable-pod

# 2. Update kernel (high priority)
sudo apt-get update && sudo apt-get install linux-image-generic

# 3. Enforce security policies
apiVersion: policy/v1beta1
kind: PodSecurityPolicy
metadata:
  name: restricted
spec:
  privileged: false
  allowPrivilegeEscalation: false
  requiredDropCapabilities:
  - ALL
  runAsUser:
    rule: 'MustRunAsNonRoot'
  seLinux:
    rule: 'MustRunAs'
  readOnlyRootFilesystem: true

# 4. Scan base images regularly
trivy image ubuntu:22.04 --exit-code 1 --severity HIGH,CRITICAL

# 5. Use minimal base images  
FROM alpine:3.17  # Much smaller attack surface

    Practice Questions

    1. Question: Should containers run as root?

    2. Answer: No. Run as non-root user (UID > 0). If compromised, attacker limited to that user.

    3. Decision: Multi-stage build vs single-stage?

    4. Answer: Always multi-stage. Reduces image size 5-10x. Smaller = less attack surface.

    5. Scenario: Found critical CVE in base image. What to do?

    6. Answer: Update base image. Rebuild container. Re-scan. Re-deploy. Hourly if critical.

    7. Comparison: Alpine vs Ubuntu as base?

    8. Alpine: 7MB (minimal, fast)
    9. Ubuntu: 77MB (more tools, slower) Alpine = better security + performance.

    Container Supply Chain Security

    Image Provenance & Attestation

    # Sign container image with Cosign
cosign sign --key cosign.key myregistry.azurecr.io/myapp:latest

# Verify signature before running
cosign verify --key cosign.pub myregistry.azurecr.io/myapp:latest

# Create detailed attestation (SLSA framework)
cosign attest --key cosign.key \
  --predicate attestation.json \
  myregistry.azurecr.io/myapp:latest

# Verify the entire supply chain
cosign verify-attestation --key cosign.pub \
  myregistry.azurecr.io/myapp:latest

    Runtime Image Verification

    # Kubernetes policy: Only run signed images
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingWebhookConfiguration
metadata:
  name: image-signature-validation
webhooks:
- name: signature.example.com
  clientConfig:
    service:
      name: signature-verifier
      namespace: security
      path: "/verify"
    caBundle: LS0tLS1...
  rules:
  - operations: ["CREATE"]
    apiGroups: [""]
    apiVersions: ["v1"]
    resources: ["pods"]
  admissionReviewVersions: ["v1"]
  sideEffects: None
