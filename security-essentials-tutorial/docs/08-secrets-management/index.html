    Secrets Management

    Overview

    Secrets Management protects sensitive data (passwords, API keys, certificates, tokens) throughout their lifecycle: creation, storage, access, rotation, and revocation.

    Mental Model

    Secrets Lifecycle:

┌─────────────────┐
│ Create Secret   │
│ (Random, long)  │
└────────┬────────┘
         │
┌────────▼────────────────────┐
│ Store Securely              │
│ - Encrypted at rest         │
│ - Access controlled (RBAC)  │
│ - Separate from code        │
└────────┬────────────────────┘
         │
┌────────▼────────────────────┐
│ Access from App             │
│ - Audit who accessed        │
│ - Rate limit access         │
│ - Log every use             │
└────────┬────────────────────┘
         │
┌────────▼────────────────────┐
│ Rotate Periodically         │
│ - Monthly/quarterly         │
│ - Change without downtime   │
│ - Revoke old secret         │
└────────┬────────────────────┘
         │
┌────────▼────────────────────┐
│ Revoke When Needed          │
│ - Employee leaves           │
│ - Breach detected           │
│ - No longer needed          │
└────────────────────────────┘

Goal: Secrets never visible to unauthorized parties
      Secret exposure = immediate revocation & rotation

    Secrets Storage Patterns

    ❌ WRONG: Secrets in Code/Environment Variables

    # config.py
DATABASE_PASSWORD = "my_secure_password_123"  # ❌ In source code!
AWS_ACCESS_KEY = "AKIA..."  # ❌ In source code!

# Or in .env file
cat .env
DATABASE_PASSWORD=my_secure_password_123
AWS_ACCESS_KEY=AKIA...
# ❌ In repo history forever (even if deleted)

# Or in environment variables
docker run -e DATABASE_PASSWORD=secret123 myapp  # ❌ Visible in docker inspect

    ✅ CORRECT: HashiCorp Vault

    Centralized secrets management with encryption, rotations, and audit logging:

    # 1. Start Vault server
vault server -config=config.hcl

# 2. Write a secret
vault kv put secret/database \
  username=admin \
  password="$(openssl rand -base64 32)"

# 3. Applications read from Vault (never stored locally)
curl -s -H "X-Vault-Token: $VAULT_TOKEN" \
  http://localhost:8200/v1/secret/data/database | \
  jq '.data.data.password'

# 4. Vault automatically rotates credentials
vault write -f database/rotate-root/mydb
# Old password revoked, new password in Vault

# 5. Audit all access
vault audit list
# Who accessed what, when

    ✅ AWS Secrets Manager

    # Create secret
aws secretsmanager create-secret \
  --name prod/database-password \
  --secret-string "$(openssl rand -base64 32)"

# Retrieve secret
aws secretsmanager get-secret-value \
  --secret-id prod/database-password \
  --query SecretString

# Auto-rotate (Lambda function)
aws secretsmanager update-secret \
  --secret-id prod/database-password \
  --rotation-rules AutomaticallyAfterDays=30

# Audit with CloudTrail
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=ResourceType,AttributeValue=AWS::SecretsManager::Secret

    Kubernetes Secrets

    External Secrets Operator (Fetch from Vault)

    # Install external-secrets
helm repo add external-secrets https://charts.external-secrets.io
helm install external-secrets external-secrets/external-secrets

# Configure Vault backend
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: vault-backend
spec:
  provider:
    vault:
      server: "https://vault.example.com"
      path: "secret"
      auth:
        kubernetes:
          mountPath: "kubernetes"
          role: "myapp-role"

---
# Fetch secrets from Vault into K8s
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: database-secret
spec:
  secretStoreRef:
    name: vault-backend
  target:
    name: database-credentials  # K8s secret created here
  data:
  - secretKey: username
    remoteRef:
      key: database
      property: username
  - secretKey: password
    remoteRef:
      key: database
      property: password

---
# Pod uses the synced K8s secret
apiVersion: v1
kind: Pod
metadata:
  name: myapp
spec:
  containers:
  - image: myapp:1.0
    name: app
    env:
    - name: DB_USER
      valueFrom:
        secretKeyRef:
          name: database-credentials
          key: username
    - name: DB_PASSWORD
      valueFrom:
        secretKeyRef:
          name: database-credentials
          key: password

    Sealed Secrets (Encrypt K8s Secrets)

    # Install Sealed Secrets
kubectl apply -f https://github.com/bitnami-labs/sealed-secrets/releases/download/v0.22.0/controller.yaml

# Create secret
kubectl create secret generic db-creds \
  --from-literal=username=admin \
  --from-literal=password=secret123 \
  -o yaml > my-secret.yaml

# Seal it (encrypt with cluster key)
kubeseal -f my-secret.yaml -w sealed-secret.yaml

# Now safe to commit to git ✓
cat sealed-secret.yaml  # Shows encrypted data

# When applied, K8s decrypts automatically
kubectl apply -f sealed-secret.yaml

# Secret is decrypted and used by pods

    Secret Rotation Strategy

    Database Password Rotation

    from vault import VaultClient
from database import Database
import time

class RotationManager:
    """Manage database credential rotation"""

    def __init__(self, vault_url, secret_name):
        self.vault = VaultClient(vault_url)
        self.secret_name = secret_name

    def rotate_password(self, db_connection_string):
        """Rotate database password without downtime"""

        # 1. Check current password
        current_creds = self.vault.read(self.secret_name)
        db = Database(db_connection_string, current_creds)

        # 2. Generate new password
        new_password = self.vault.generate_random_secret(length=32)

        # 3. Update database
        with db.connection() as conn:
            # Update root password
            conn.execute(
                f"ALTER USER {current_creds['username']} " +
                f"WITH PASSWORD '{new_password}'"
            )

        # 4. Test new credentials
        db_test = Database(db_connection_string, {
            'username': current_creds['username'],
            'password': new_password
        })

        if not db_test.health_check():
            raise Exception("Credentials test failed")

        # 5. Update in Vault
        self.vault.write(self.secret_name, {
            'username': current_creds['username'],
            'password': new_password
        })

        # 6. No downtime: Apps fetch new password on next request
        print(f"✓ Password rotated for {self.secret_name}")

    def auto_rotate(self, interval_days=30):
        """Auto-rotate every 30 days"""

        while True:
            time.sleep(interval_days * 86400)  # 30 days

            try:
                self.rotate_password()
            except Exception as e:
                print(f"❌ Rotation failed: {e}")
                # Alert on-call

# Usage
manager = RotationManager("https://vault.mycompany.com", "database/prod")
manager.auto_rotate(interval_days=30)

    API Key Rotation

    class APIKeyRotation:
    """Auto-rotate API keys"""

    def generate_new_key(self):
        """Create new API key"""
        import secrets
        return secrets.token_urlsafe(32)

    def rotate_with_zero_downtime(self, service_name):
        """Rotate key while service keeps running"""

        # 1. Create new key
        new_key = self.generate_new_key()

        # 2. Store new key in secrets manager
        self.secrets_manager.create(
            f"{service_name}_api_key",
            new_key
        )

        # 3. Keep old key working for 30 minutes (grace period)
        # Apps can use either old or new key
        old_key_grace_period = 1800  # seconds

        # 4. After 30 min, revoke old key
        time.sleep(old_key_grace_period)

        # 5. Mark old key as revoked
        self.secrets_manager.mark_revoked(
            f"{service_name}_api_key_old"
        )

        print(f"✓ API key rotated for {service_name}")

    def schedule_rotations(self):
        """Rotate all keys monthly"""

        services = ['payment-api', 'notification-api', 'analytics-api']

        for service in services:
            schedule.every(30).days.do(
                self.rotate_with_zero_downtime,
                service
            )

        while True:
            schedule.run_pending()
            time.sleep(60)

    Fine-Grained Access Control

    # Vault: Only specific apps can access specific secrets
apiVersion: vault.banzaicloud.com/v1alpha1
kind: Vault
metadata:
  name: vault
spec:
  # Policy: Only payment-service can access payment API key
  policies:
  - name: payment-service-policy
    content: |
      path "secret/data/payment-api-key" {
        capabilities = ["read", "list"]
      }
      path "secret/data/payment/*" {
        capabilities = ["read", "list"]
      }

  # Bind policy to Kubernetes service account
  - name: web-service-policy
    content: |
      path "secret/data/web/*" {
        capabilities = ["read", "list"]
      }

---
# Kubernetes: Bind policy to service account
apiVersion: v1
kind: ServiceAccount
metadata:
  name: payment-service
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: vault-auth
rules:
- apiGroups: ["vault.banzaicloud.com"]
  resources: ["vaults"]
  verbs: ["get", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: vault-auth-payment
subjects:
- kind: ServiceAccount
  name: payment-service
roleRef:
  kind: ClusterRole
  name: vault-auth

    Encryption Key Management

    Hardware Security Module (HSM)

    For highest security, store encryption keys in dedicated hardware:

    # Connect to HSM (Thales Luna HSM, Fortanix, etc.)
# HSM generates and stores keys that never leave the device

# Use AWS CloudHSM
aws cloudhsm create-cluster \
  --hsm-type hsm1.large \
  --subnet-ids subnet-xxx

# Use key from HSM for data encryption
# App never sees raw key, only encrypted data + key reference
aws kms encrypt \
  --key-id arn:aws:kms:region:account:key/cmk-id \
  --plaintext "sensitive data"

# Key stays in HSM, decryption happens in HSM boundary
# Protects against memory dumps, theft, etc.

    Key Rotation for Encryption

    class EncryptionKeyRotation:
    """Manage encryption key lifecycle"""

    def __init__(self, kms_client):
        self.kms = kms_client

    def rotate_encryption_key(self, key_id):
        """
        Rotate encryption key for new data
        Old data stays encrypted with old key
        (Re-encryption on demand)
        """

        # 1. Enable automatic key rotation
        self.kms.enable_key_rotation(KeyId=key_id)
        # AWS rotates key annually automatically

        # 2. For immediate rotation:
        # Create new key
        new_key = self.kms.create_key(
            Description="Rotated encryption key"
        )
        new_key_id = new_key['KeyMetadata']['KeyId']

        # 3. For existing encrypted data needing re-encryption:
        # Batch re-encrypt data with new key
        for encrypted_item in self.get_encrypted_items():
            # Decrypt with old key
            plaintext = self.kms.decrypt(
                CiphertextBlob=encrypted_item['data']
            )

            # Encrypt with new key
            new_encrypted = self.kms.encrypt(
                KeyId=new_key_id,
                Plaintext=plaintext['Plaintext']
            )

            # Update storage
            self.update_item(
                encrypted_item['id'],
                new_encrypted['CiphertextBlob']
            )

        # 4. Disable old key (don't delete, keep for edge cases)
        self.kms.disable_key(KeyId=key_id)

        return new_key_id

    Secrets Scanning & Detection

    Prevent Secrets in Code

    # Install git-secrets
brew install git-secrets

# Setup for repo
cd /path/to/repo
git secrets --install
git secrets --register-aws

# Add custom patterns
git secrets --add 'api_key.*=.*[a-zA-Z0-9]{32,}'

# Pre-commit will now block secrets
git add config.py  # Contains: API_KEY=...
# ❌ Error: AWS credentials found in config.py

# Or use detect-secrets
pip install detect-secrets

# Scan for secrets
detect-secrets scan src/ --baseline .secrets.baseline

# Verify no secrets in commits
detect-secrets audit .secrets.baseline

    Production Secret Detection

    class SecretDetectionMonitor:
    """Detect secrets leakage in production logs"""

    # Patterns that match common secrets
    SECRET_PATTERNS = [
        r'password\s*=\s*["\']([^"\']+)["\']',
        r'api[_-]?key\s*[=:]\s*["\']?([a-zA-Z0-9_]+)["\']?',
        r'bearer\s+([a-zA-Z0-9_\-\.]+)',
        r'(sk_live|sk_test)[a-zA-Z0-9_\-]+',  # Stripe keys
        r'AWS_SECRET_ACCESS_KEY\s*=\s*([a-zA-Z0-9/+=]+)',
    ]

    def scan_logs(self, log_stream):
        """Scan CloudWatch/ELK logs for leaked secrets"""
        import re

        for log_entry in log_stream:
            for pattern in self.SECRET_PATTERNS:
                match = re.search(pattern, log_entry['message'])
                if match:
                    # Secret matched!
                    self.alert({
                        'level': 'CRITICAL',
                        'secret_type': pattern,
                        'source': log_entry['source'],
                        'timestamp': log_entry['timestamp']
                    })

                    # Immediately revoke this secret
                    self.revoke_secret(match.group(1))

    def revoke_secret(self, secret_value):
        """Revoke potentially exposed secret"""

        # For API keys: find which service owns it
        # For passwords: force reset
        # For tokens: blacklist immediately

        print(f"⚠️  Revoking exposed secret")

    Common Mistakes

    Mistake 1: Secrets in .env files committed to git 

    # ❌ WRONG
cat .env
DB_PASSWORD=secret123
API_KEY=abc123...

git add .env
git commit -m "Setup env"
# Secret in repo history forever, even if deleted

# ✅ CORRECT
# Add to .gitignore
echo ".env" >> .gitignore

# Create .env.example with placeholders
cat .env.example
DB_PASSWORD=CHANGE_ME
API_KEY=CHANGE_ME

# Use git-secrets to prevent commits
git secrets --install
git secrets --aws-provider

    Mistake 2: Rotating without updating clients 

    # ❌ WRONG
# Rotate password in database
ALTER USER admin WITH PASSWORD 'newpassword';

# Old clients still use old password
# App crashes: "Authentication failed"

# ✅ CORRECT
# 1. Update all clients first
# 2. Then rotate password
# Or: Keep old password valid for grace period

    Mistake 3: Storing secrets in application logs 

    # ❌ WRONG
logging.info(f"Connecting as {username}:{password}")
# Password in logs forever

# ✅ CORRECT
logging.info(f"Connecting as {username}")  # Don't log password
# Or: Log access event without secret
logging.info(f"Secret {secret_name} accessed by {user_id}")

    Mistake 4: Using weak secret generation 

    # ❌ WRONG
import random
password = ''.join(random.choices('abc123', k=8))
# Weak: Only 6^8 = 1.6M possibilities, predictable

# ✅ CORRECT
import secrets
password = secrets.token_urlsafe(32)
# Strong: 2^256 possibilities, cryptographically random

# Or use secret manager's generation
vault write -f transit/datakey/myapp
# Vault generates strong key

    Mistake 5: No secret rotation policy 

    # ❌ WRONG
# Create secret once
# Use forever
# If leaked: Impact is forever

# ✅ CORRECT
# Rotate every 30 days
# Manual or automated refresh
# Limit window of exposure

    Mistake 6: Sharing secrets across environments 

    # ❌ WRONG
# Same API key for dev, staging, prod
export API_KEY="prod_key_123"
# If dev leaked: prod also compromised!

# ✅ CORRECT
# Separate secret per environment
vault read secret/dev/api-key      # Different key
vault read secret/staging/api-key  # Different key
vault read secret/prod/api-key     # Different key
# Breach in one env doesn't affect others

    Production Incident: Leaked API Key

    Scenario: "Developer hardcoded API key in code, committed to public repo"

    Timeline: 

    12:00 - Developer commits API key by mistake
12:15 - Commit pushed to GitHub
12:30 - Attacker finds key via GitHub search
12:45 - Attacker uses key to make API calls
13:00 - Alert fires (unusual API usage pattern)
13:05 - We detect key in repo history

    Immediate Response: 

    # 1. Revoke key immediately
vault delete secret/api-keys/leaked-key

# 2. Check what attacker accessed
# Query: Last 1 hour of API logs for suspicious calls
grep "leaked-key" /var/log/api-access.log | \
  jq 'select(.timestamp > "13:00" and .timestamp < "14:00")'

# 3. Change key and update all services
vault write secret/api-keys/production \
  key="$(openssl rand -base64 32)"

# 4. Update service
kubectl set env deployment/myapp \
  API_KEY="$(vault kv get -field=key secret/api-keys/production)"

# 5. Remove from code history
git filter-branch --tree-filter 'rm -f config.py' --prune-empty
git push --force-with-lease

    Root Cause Analysis: - No pre-commit hook to detect secrets - Developer didn't use .gitignore - Public repository (not private) - No security scanning in CI/CD

    Prevention: 

    # Pre-commit hook
#!/bin/bash
# .git/hooks/pre-commit
git-secrets --scan || exit 1

# CI/CD scanning
- name: Scan for secrets
  run: |
    pip install detect-secrets
    detect-secrets scan || exit 1

# Repository rules
- Branch protection
- No direct pushes to main
- All pushes require review
- Scan before merge

    Multi-Cloud Secrets Management

    Managing secrets across AWS, Azure, GCP, and private clouds:

    class MultiCloudSecretsManager:
    """Unified secrets management across clouds"""

    def __init__(self):
        self.aws_secrets = None
        self.azure_secrets = None
        self.vault_client = None

    def get_secret(self, secret_name, cloud='auto'):
        """
        Get secret from any cloud provider

        Usage:
        - Multi-cloud deployment resilience
        - Vendor lock-in prevention
        - Cost optimization
        """

        if cloud == 'auto':
            # Try clouds in order of preference
            for provider in ['aws', 'vault', 'azure']:
                try:
                    return self._get_from_provider(secret_name, provider)
                except:
                    continue
        else:
            return self._get_from_provider(secret_name, cloud)

    def _get_from_provider(self, secret_name, provider):
        """Get from specific provider"""

        if provider == 'aws':
            # Get from AWS Secrets Manager
            import boto3
            client = boto3.client('secretsmanager')
            return client.get_secret_value(
                SecretId=secret_name
            )['SecretString']

        elif provider == 'azure':
            # Get from Azure Key Vault
            from azure.identity import DefaultAzureCredential
            from azure.keyvault.secrets import SecretClient

            vault_url = "https://<vault-name>.vault.azure.net/"
            client = SecretClient(
                vault_url=vault_url,
                credential=DefaultAzureCredential()
            )
            return client.get_secret(secret_name).value

        elif provider == 'vault':
            # Get from HashiCorp Vault
            return self.vault_client.secrets.kv2.read_secret_version(
                path=secret_name
            )['data']['data']

# Usage in multi-cloud app
manager = MultiCloudSecretsManager()

# App auto-detects available cloud and retrieves secret
api_key = manager.get_secret('api/stripe-key')

    Secrets Compliance & Regulatory

    Ensure secrets management meets compliance requirements:

    from datetime import datetime

class SecretsComplianceAuditor:
    """Audit secrets against compliance frameworks"""

    COMPLIANCE_REQUIREMENTS = {
        'PCI-DSS': {
            'secret_rotation': '90 days',
            'min_length': 7,
            'complexity': True,
            'audit_logging': True,
        },
        'HIPAA': {
            'encryption': 'AES-256',
            'access_control': 'role-based',
            'audit_required': '6 years',
            'transmission': 'TLS 1.2+',
        },
        'SOC2': {
            'access_control': True,
            'change_management': True,
            'audit_logging': True,
            'incident_response': True,
        },
        'ISO27001': {
            'secret_rotation': '180 days',
            'encryption': True,
            'access_control': True,
            'asset_tracking': True,
        },
    }

    def audit_secrets(self, secrets_config, framework):
        """Check if secrets meet compliance requirements"""

        requirements = self.COMPLIANCE_REQUIREMENTS[framework]
        findings = {
            'compliant': True,
            'violations': []
        }

        # Check encryption
        if requirements.get('encryption'):
            if secrets_config.get('encryption') != 'AES-256':
                findings['compliant'] = False
                findings['violations'].append({
                    'item': 'encryption',
                    'required': 'AES-256',
                    'current': secrets_config.get('encryption')
                })

        # Check rotation
        if requirements.get('secret_rotation'):
            rotation_days = int(
                requirements['secret_rotation'].split()[0]
            )
            if secrets_config.get('rotation_days', 365) > rotation_days:
                findings['compliant'] = False
                findings['violations'].append({
                    'item': 'rotation_frequency',
                    'required': f'{rotation_days} days',
                    'current': f"{secrets_config.get('rotation_days')} days"
                })

        # Check audit logging
        if requirements.get('audit_logging'):
            if not secrets_config.get('audit_enabled'):
                findings['compliant'] = False
                findings['violations'].append({
                    'item': 'audit_logging',
                    'required': 'Enabled',
                    'current': 'Disabled'
                })

        return findings

    def generate_compliance_report(self, framework):
        """Generate compliance report for audit"""

        audit_findings = self.audit_secrets(
            self.get_current_config(),
            framework
        )

        report = {
            'framework': framework,
            'audit_date': datetime.now().isoformat(),
            'compliant': audit_findings['compliant'],
            'violations': audit_findings['violations'],
            'recommendations': self._generate_recommendations(
                audit_findings['violations']
            ),
            'remediation_deadline': self._calculate_deadline(framework)
        }

        return report

    Practice Questions

    1. Question: Where should secrets be stored?

    2. Answer: Never in code. Use: Vault, AWS Secrets Manager, K8s External Secrets operator.

    3. Decision: How often rotate secrets?

    4. Answer: High-risk (API keys): 30 days. Database: 90 days. Certificates: 365 days.

    5. Scenario: Secret leaked. First action?

    6. Answer: Revoke immediately. No grace period for leaked secrets. Update all clients. Log incident.

    7. Comparison: .env file vs Vault?

    8. .env: Simple, local, insecure
    9. Vault: Centralized, encrypted, audited, rotated
